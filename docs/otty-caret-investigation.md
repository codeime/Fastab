# Otty 光标与补全排查

日期：2026-09-29。现场版本：Otty 1.5.4、Fastab 0.0.3（已安装构建来自 `8b03c705`）。本记录区分已安装版本的现场证据和本次源码修复，不能用单元测试代替安装后的定位验收。

## 现场证据

- Fastab 桌面进程报告辅助功能权限正常；Otty 新建终端的 shell 集成已工作，输入 `git ` 和后续增删能更新桌面收到的编辑缓冲。
- Otty 位于前台时，桌面发出了获取光标的输入法通知；临时透明 IPC 采集期间收到的光标帧为零。采集完成后已恢复原始 socket，并停止临时详细日志。
- Fastab 输入法进程存活，安装路径和软链接正确。两份 HIToolbox 持久列表均包含 Fastab，但新查询的 TIS source 是 `enabled=0, selected=1`；持久配置不能证明运行时连接已建立。
- 在真实 AppKit run loop 中，对自己的已禁用 source 调用 `TISEnableInputSource` 返回成功，但重新获取仍是禁用状态，且系统打开了“键盘”设置。因此没有把该调用加回自动恢复路径，也没有禁用/重启输入法或要求用户增加设置步骤。
- [Otty 官方辅助功能文档](https://docs.otty.sh/reference/accessibility)说明 1.2.0 起提供终端文本范围与插入点。现场辅助功能树确实把当前终端暴露为聚焦的 text entry area。原代码将 Otty 限定到输入法坐标路径，没有尝试 AX 插入点；能否取得可用坐标仍需更新后的桌面进程验证。

## 修复边界

对已确认运行版本为 1.2+ 的 Otty 使用辅助功能插入点，旧版、未知版本保留输入法路径；版本读取按实际运行进程的 bundle 与启动时间缓存。检查前台应用、焦点窗口与文本元素，不从窗口边框、终端字体或行列数估算坐标。查询失败时清除旧位置，避免下一次候选返回又显示在旧坐标；迟到的输入法帧不能覆盖 Otty 的直接光标位置。

焦点处理同时修复延迟事件隐藏新窗口、旧异步启用状态覆盖新终端、辅助功能临时错误被当成窗口销毁的问题。辅助功能查询共用 250 ms 预算，失败后退避 750 ms。输入法状态涉及的 SQLite 查询保留在后台，响应绑定窗口与独立序号，避免阻塞界面或误用旧响应。

这些修改不重启 Otty 或输入法，不改用户的系统授权，不新增设置项。新版本的具体 AX 返回值、旧版输入法兼容以及跨屏实际落点需要安装后验收，不能从文档或源码检查推断。
