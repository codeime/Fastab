# 独立自然语言命令生成模式设计

日期：2026-09-29。状态：设计稿，本轮不实现，也未验证任何生成服务。

## 用户流程与边界

用户从 Fastab 菜单明确选择“生成命令…”，或使用将来单独配置的终端快捷键。入口只在一个已连接、位于 shell 提示符且编辑行为空的 `fastabterm` 会话可用；无法确定目标会话时，显示原因并禁止生成。现有 `?` 是项目或个人快捷建议入口，不复用；普通候选、Tab、Enter、Jev 自动推荐的时序保持独立。

模式打开后使用单独 GPUI 窗口输入自然语言意图。用户点击“生成”才发起请求。窗口显示完整、可编辑的单行命令和独立的可选说明；命令区不截断隐藏尾部，支持滚动或换行显示。用户可以修改命令，再点击“插入到终端”。该按钮只写入编辑行，不发送回车，也不运行命令。用户回到终端自行检查和执行。Esc/取消、关闭窗口和会话失效都丢弃结果，不更改终端。

首版只向服务发送用户在此窗口输入的意图和 shell 类型；不自动附带 cwd、路径、环境变量、最近命令、Git 分支或状态、终端输出。用户提出“修复这个错误”时，只能由用户主动粘贴或选择要发送的错误文本，并在发送前显示实际范围；现有 Jev 上下文不发送退出码或 stderr，生成模式也不自动读取，不能宣称会自动理解上次命令是否成功。输入、输出和解释均有明确字节上限，不写入诊断、遥测或调试日志。

## 服务与配置

当前 Jev System One 请求在 `crates/fastab_desktop/src/jev/types.rs` 中要求模型从已有候选 ID 中选一项。它没有自由文本命令生成契约。生成模式必须使用独立的服务适配器、请求/响应类型、启用开关和数据披露，不能把推荐提示词改成“生成命令”。现有 Jev profile、API Key 或已保存的 `share_git_status` 配置都不能自动授权此模式；当前 AI 设置已撤下 Git 状态开关和本机会话诊断卡，本轮不新增生成模式操作。

服务商、模型、端点和认证方式尚未决定。选型前需以真实协议验证：请求格式、最大响应、费用、超时、取消、错误码、数据保留和供应商条款。只有服务适配器经过这些验证且用户单独启用后才允许网络请求。请求必须限定 HTTPS、拒绝重定向、限制请求与响应体、禁止默认日志记录正文；配置和凭据变更立即取消在途生成。限流、冷却和失败只在窗口中反馈，不触发自动重试。

适配器内部的规范化接口建议为：`GenerateCommandInput { intent, shell, user_supplied_error? }`，返回 `GeneratedCommand { command, explanation? }`。这些字段是设计接口，并非已验证的供应商 API。返回必须是完整 JSON 对象，拒绝未知或重复关键字段、空命令、超长文本、换行、回车、NUL、控制字符和终端转义序列。说明文字只展示，不进入插入流。命令可以包含 shell 运算符；预览必须逐字显示，不能以不完备的“安全”判断代替用户确认。

## 会话与插入状态机

开启时捕获目标 `session_id`、shell、编辑缓冲区、光标和会话修订。窗口只有 `输入意图 → 生成中 → 完整预览 → 明确确认 → 等待插入结果` 五个可行动状态；每次修改意图或上下文都会使旧结果和请求令牌失效。只能存在一个在途请求。会话断开、命令开始执行、编辑行不再为空、用户切换目标终端、配置改变、窗口关闭或请求超时后，确认按钮失效并说明原因。

确认时先对用户编辑后的最终命令重新执行完整的长度、换行和控制字符校验，桌面端再核对会话、提示符、原编辑行与光标。仅桌面端检查不够：当前 `proto/figterm.proto` 的 `InsertTextRequest.insertion_buffer` 在 `fastab_term/src/message.rs` 中用于补偿缓冲区变化，不能作为严格门禁。实施时新增明确的“预期原缓冲区和光标必须完全匹配”协议字段和 PTY 端原子检查；不匹配就拒绝，不尝试补全或覆盖用户新输入。需要带请求 ID 的插入结果反馈，区分“已写入编辑行”和“请求已排队”；没有 PTY 确认时不能宣称插入成功。

匹配后由专用插入路径发送原样命令，固定 `immediate=false`、`insert_during_command=false`、无 `\n`/`\r`、不追加自动空格，不走 `insertSelectedAndExecute`、`auto-execute` 或普通候选的 `insertValue` 逻辑。焦点恢复到原终端后，用户仍需亲自按 Enter。无 shell 提示符或无法确认缓冲区时保持预览并提示重试，不降级为剪贴板粘贴或向另一会话发送。

## 实施前验证矩阵

| 场景 | 必须观察到的行为 |
| --- | --- |
| 空提示符、明确输入并生成 | 仅点击“生成”后发请求；完整命令先预览 |
| 普通 `?`、Tab、Enter 和 Jev 推荐 | 继续走原路径，不打开生成窗口 |
| 非空编辑行、命令运行中、会话断开 | 禁止生成或插入，显示原因 |
| 生成过程中改意图、切会话或关闭窗口 | 旧响应失效，绝不插入 |
| 预览后终端缓冲区或光标改变 | PTY 严格拒绝，不补偿或覆盖 |
| 恶意/损坏响应、超长输出、换行和 ANSI 序列 | 拒绝显示为可插入命令，不执行 |
| 用户修改预览、确认插入 | 插入完整当前文本，不附加回车；仅在 PTY 确认后报告成功 |
| 服务超时、鉴权或额度错误 | 独立窗口反馈；普通本地补全继续工作 |
| 用户粘贴错误文本 | 发送前显示范围；未粘贴时不读取 stderr |

落地顺序：先确定并验证供应商契约与披露文案，再实现独立 GPUI 输入/预览和会话状态，随后增加 PTY 严格插入确认，最后做真实终端交互验收。设计通过不代表服务协议、视觉体验或插入行为已通过运行验证。
