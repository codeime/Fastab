# AI 补全体验改进实施计划

日期：2026-09-29。基线提交：`eb6ee0f9`。依据：`ai-completion-ux-review.md` 和当前 Rust/GPUI 实现。

## 目标与范围

让已有候选推荐覆盖有用场景、及时且不打断选择，并让用户在设置中看清参与情况；动态参数优先改善项目内的本地排序。用户已确认：独立自然语言命令生成本轮只完成设计。

本轮实现不改变 Jev 的“选择已有候选 ID”契约，不自动执行命令，不上传新的动态候选、路径或文件内容。新增结构化 Git 状态默认关闭，用户在 AI 设置单独开启。普通列表继续安静回退。

完成标准是实现项有代码、有效验证和复核记录，设计项有完整设计产物，无已知未处理的阻塞问题；不以“完美”代替运行证据，不把离线回归说成真实模型收益。

## 实施顺序、验收和复核重点

依赖关系：S1、S3 的统计基础和 S4 的采集/配置互相独立，可以并行；S2 在 S1 引擎改动复核后继续；S5 在 S3/S4 接口稳定后集成；S6 设计可并行。每块进入下一依赖阶段前必须完成自身 review & fix，S7 覆盖最终组合。

### S1 候选覆盖与请求必要性

1. 静态来源采集时保留所有通过校验的候选资格，不在字母序采集阶段消耗 20 项预算。
2. 保留去重前的来源冲突检查：同名静态/动态或历史候选不能因本地去重获得公开资格。移除平方级扫描，按已标记名称进行有界冲突检查。
3. 本地历史合并、匹配、接受记录和优先级排序完成后再截取最多 20 项；最终仍核对前缀、危险标记、插入元数据和来源。
4. 唯一合格候选继续直接使用本地结果；不人为调整模型 confidence 阈值。只有真实首项也合格时，才保证首项在推荐集合中。
5. 核查当前编译器、锁定 spec 来源与固定公开基线的关系。已定位本机 IR marker 仍指向含旧运行时 JS 的 4816 文件生成树，当前源码清单与安装包 pins 一致；用当前编译器离线重建，随后校验三份摘要。不得直接改 pins 放行。

验收：超过 20 项的测试中，原来位于字母序尾部、经本地接受记录排在首位的候选进入 AI 集合；上限、重复来源、生成中、别名/选项值/管道等拒绝行为保留；公开基线校验保持有效。复核实际 runtime 顺序，避免测试只调用孤立 helper。

### S2 项目和参数上下文内的本地排序

1. 用解析后的真实命令路径/参数槽与 cwd 建立作用域；不把任意第二个 token 当作子命令。
2. 分支、项目脚本和容器等参数候选的接受记录在作用域内生效；项目 A 的选择不得提高项目 B 同名参数的优先级。
3. 保留现有全局命令/选项记录和旧数据可读性；参数作用域记录采用独立版本键，不破坏旧 JSON。参数排序不回退到旧 root+name 全局记录，也不使用无 cwd 的全局 next-word 频次抬高参数候选，否则旧选择仍会跨项目污染；未有作用域记录时保持原有匹配/优先级稳定顺序。
4. 接受成功后才记录；作用域绑定解析器参数来源（优先 ArgSlot），随候选一路传到接受动作，不能在接受时按新输入重新猜测。混合列表里的命令、选项和历史整行不套参数作用域。保留候选插入元数据、alias、字符转义、精确/前缀/模糊匹配桶、特殊行顺序及用户指定的字母序行为。
5. 新记录数量及持久化体积有上限，使用现有 worker 保存，不能在 GPUI 输入线程新增数据库等待。首版只记接受时间戳，保持客户端先记、worker 重放时的幂等，不引入双计数。

验收：同目录同子命令复用、不同目录/子命令/参数槽隔离、旧记录兼容、失败插入不记录、字母序不受学习影响、动态候选仍不外发。复核从接受到 worker 再到下一次排序的完整链路。

### S3 本机诊断与可解释统计

1. 引入进程内有界统计，不保存原始输入、路径、候选名、密钥、请求或响应正文，不增加遥测上报。
2. 区分本地评估、可参与、实际请求、缓存命中、服务返回、保持本地、实际改变排序、采用、跳过和取消；选择第 0 项不能算排序提升。实际请求在序列化/凭据验证通过、进入 HTTP send 时计数，不复用在上下文采集前增加的 admitted 配额记录。
3. 显示最后一个可解释状态：未启用/配置未就绪/来源或场景不支持/候选不足/导航中/冷却或频率限制/超时或服务错误等。
4. 记录有限数量的请求耗时样本，展示样本数与延迟摘要；明确缓存与网络耗时的口径。
5. AI 设置增加本机会话诊断卡，可刷新和清零。UI 展示聚合数据，保持已有自动保存、语言和键盘操作行为。
6. 采用统计绑定 InsertText 成功入队，这是现有产品可观察的边界，不能声称已收到 shell 落地或执行 ACK。清理 AI 状态前捕获曝光身份，同一曝光只结算一次；未采用不直接等同“模型错误”。KEEP_LOCAL、初始化新请求和普通清理不能借 cancel_jev 重复记作取消。

验收：正常/拒绝/取消/过期/缓存各路径不会重复计数；清零后旧请求不污染新统计；迟到响应不覆盖新状态；诊断序列化不包含敏感文本；设置卡实际渲染可读。

### S4 有界结构化 Git 状态

1. 新增默认关闭的独立设置，说明只增加“有工作区修改、已暂存、冲突、未跟踪文件”等状态；已有分支和近期命令的数据范围不悄悄变化。
2. 在后台、现有上下文时间预算内采集本地 Git 状态；禁用可执行 fsmonitor hook，清理会改变 Git 目标的环境变量，不联网或执行项目脚本。
3. 输出字节数、进程寿命和解析条目均有上限；明确区分“已确认非仓库/没有分支/没有近期历史”和“超时/查询失败/损坏输出”。后者是不完整上下文，不能当作“工作区干净”或空历史。
4. 仅明确开启时加入请求；切换设置立即废弃旧请求和缓存。Git 状态不改成本地硬编码的“推荐 commit/reset”等规则，避免把任务意图猜错。
5. 本地缓存验证可使用不外发的状态摘要；任何路径/文件名都不进入新增序列化字段。
6. 历史查询单独限并发，许可由实际 blocking 查询持有至结束；取消/超时的 future 不能释放许可后继续无界启动数据库读取。Git 子进程也必须在取消时结束。

验收：干净/修改/暂存/冲突/重命名/未跟踪、非 UTF-8 文件名、非仓库、超限/超时和关闭状态；保存旧配置时新增字段默认关闭；请求结构只含批准的布尔状态。

### S5 短时推荐缓存与稳定失效

1. 只缓存合法推荐身份（含 keep_local），不缓存 shell 插入文本。进程内最多 64 项，TTL 15 秒；无磁盘缓存。
2. 键覆盖当前输入、真实候选集合及顺序/插入身份、shell、cwd、会话、上下文版本、服务地址/模型和配置/凭据修订；用摘要而非原始上下文做缓存键。
3. 每次复用前重新获取有界上下文；超时或不完整上下文不命中缓存。配置、凭据、会话和目录变化不能复用旧结果。
4. 缓存命中仍走相同 token、导航和候选元数据校验。横滑、上下选择、粘贴、继续输入之后，迟到结果不能改列表。
5. 命中不消耗实际 HTTP 配额；冷却/鉴权失败不能被缓存绕过。不缓存失败，不自动重试，不扩大原有单请求并发。
6. 网络返回后再次有界采集并比较 Git/历史摘要，变化或不完整时丢弃该次建议且不写缓存；复用时同样重新验证。Token 只证明输入/会话有效，不能替代外部 Git/历史版本检查。缓存命中前的采集仍受独立并发限制，不因不消耗 HTTP 配额而放大后台工作。

验收：同输入同上下文命中；任一关键维度改变 miss；TTL/容量淘汰；错误不缓存；keep_local 可复用；过期响应、用户横滑、接受、设置变更与缓存命中竞态；本地列表不等待 HTTP。

### S6 独立命令生成设计（本轮不实现）

产出独立设计，明确用户主动入口、服务配置/协议、最少上下文、返回结构校验、预览编辑、确认插入、不自动执行、取消与过期输入保护、错误反馈和测试矩阵。与已有 `?` 快捷建议、Tab/Enter 和 Jev 配置分开，不伪装成现有 Choice 请求。尚未选定的生成服务作为上线前决策项，不虚构已验证的供应商兼容性。

### S7 综合评估与最终 review & fix

1. 建立确定性回归场景：`git `、`git ch`、`git status --`、`git checkout <branch>`、`npm run <script>`、容器参数、项目切换、快速输入、上下键/横滑、设置切换、超时/冷却。
2. 用固定本地候选和人工目标记录候选是否覆盖、目标位置与选择按键数，区分无历史/全局旧记录/项目内接受记录；缓存验证记录实际请求数。
3. 本轮不使用用户密钥或真实终端历史进行外部 AI 调用。需要联网评估模型质量时，单独使用经同意的场景并报告样本口径，不能把测试推荐器的选择当成真实准确率。
4. 每步实施后先跑对应既有 crate 内的有效测试，再由未实现该模块的视角复核并修复；最后验证跨模块契约、失败路径、内存上限、配置向后兼容和用户交互。
5. 运行涉及 crate 的测试、格式检查及 Clippy；仅在修改或失败要求时重复。正常 GPU/真实终端验收与测试平台事件验证分开记录。
6. 更新评估文档、实现状态与中英文变更记录。实现阶段不继承上一轮的发布动作；提交、推送和重新打包以之后的用户授权为准。

## 初轮计划复核修正

- 将“finalize 移到排序后”修正为“来源冲突检查在去重前、预算截取在排序后”，避免混入伪装成公开候选的动态来源。
- 将“首项必须包含”限定为首项本身具有公开资格，不能为覆盖率扩大外发范围。
- 唯一候选跳过已经存在，需要保留并增加诊断，不重复造另一套规则。
- 动态参数先做本地作用域学习；远端私有候选不是解除过滤即可上线的功能。
- 不利用未经校准的 confidence 制造看似准确的阈值；不把缓存命中、置顶数或未采用比例当准确率。
- 新状态默认关闭；缓存必须在上下文重新验证后复用，不能仅按输入或 cwd 复用。

### 确定性评估口径

不读取或发送用户的真实密钥/历史进行模型评估。以下使用临时合成 spec，实际调用 `Engine::complete`，由真实解析结果获取作用域；不声称执行了 Git/npm/Docker 动态生成器，也不将结果解释为模型准确率。

| 参数场景与目标 `zeta` | 无接受记录索引 | 仅旧全局记录 | 同目录、同槽接受后 | 另一目录 |
| --- | ---: | ---: | ---: | ---: |
| `git checkout ` | 1 | 1 | 0 | 1 |
| `npm run ` | 1 | 1 | 0 | 1 |
| `docker run --network ` | 1 | 1 | 0 | 1 |

索引从 0 开始。上述固定二选一场景中，复用目录内偏好少按一次方向键；旧全局记录不再跨目录提高参数排名。另覆盖子命令、第一/第二参数槽、选项值、空 cwd 和 alphabetical 排序隔离。

候选预算样例有 26 个公开静态子命令：本地接受使字母序尾部 `z-last` 排到首位后，它进入 20 项 AI 集合，上限仍为 20；唯一候选不产生 AI 推荐上下文。同名动态来源即使随后去重，也不获得公开资格。

缓存流程样例先请求一次并经 UI 发布结果，再以同一输入和上下文复用：推荐请求仍为 1 次，命中不占第二次配额；上下文不完整时既不命中也不发请求。网络回包后 Git/历史摘要改变或采集失败，结果不能发布或缓存。这些是注入确定性响应的请求编排回归，没有访问模型服务。

工作区 IR 离线重建后的源码树摘要为 `69d4bdd9…01a7`，源码清单摘要为 `c0e22579…b866`，IR 摘要为 `6872d27a…1661`，三者均与原有 `spec_pair.rs` pins 一致，未放宽信任基线。
